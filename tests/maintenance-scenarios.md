# 文档维护场景验证

这些是代理执行场景，不是自动化测试已证明的线上行为。验证时只做本地任务推演，不向真实飞书文档写入。

| 场景输入 | 期望动作 | 必须保留／核对 |
| --- | --- | --- |
| 首次记录，已确认无本任务旧记录 | 在我的文档库新建并保存绑定 | 名称日期、document_id、URL、revision |
| 会话中有已确认URL，新增一条验证结果 | 先读原文，再局部更新对应状态；有真实变更才追加迭代 | 同一document_id、原标题日期和历史失败记录 |
| 绑定URL读取无权限 | 报告读取失败，保留绑定；不新建 | 不把权限错误判成首次记录 |
| 两篇同名候选，内容不足以区分 | 询问目标链接，等待定位 | 不随机选择、不覆盖、不重复创建 |
| 再次调用，没有新增事实 | 返回原链接和无新增事实 | 不重复追加轮次或源码 |
| 旧文档有开场、待办清单、独有证据及人工补充 | 将有依据的未完成事实迁入状态表，保留证据和人工内容，再整理冗余章节 | 不批量重排其他记录、不丢资源token |
| 读后revision变化或更新请求超时 | 重读确认实际结果及并发修改，再决定局部补丁 | 不用过期草稿覆盖、不重复追加 |
| 用户明确要求另建独立快照 | 新建该快照并保留原文档 | 记录新链接；原任务绑定不自动切换 |

自动化结构与源码回读检查运行：

```bash
python3 -m unittest discover -s tests -v
```

全篇候选的人工式审阅还应检查：模块是否用适合的短表格、有没有把长段落塞进单元格、未完成事实是否准确、是否去除未来行动清单。离线检查和任务推演不能替代真实创建或更新后的回读。
