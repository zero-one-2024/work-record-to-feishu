# Feishu Work Records

[English](README.md) | [简体中文](README.zh-CN.md)

将当前 Codex 任务会话整理为结构化工作记录，并在飞书**我的文档库**（`my_library`）中新建云文档的技能。

**技能标识：** `work-record-to-feishu`

**显示名称：** Feishu Work Records

适用于开发、设计、调研、文档编制和测试等任务。技能说明与默认生成的工作记录使用中文，技能名称和标识使用英文。

## 功能

- 整理任务要求、实际完成的工作、关键决策、交付物、验证结果和后续事项。
- 文档命名为 `任务摘要_YYYYMMDD`，摘要不超过15个字符，日期采用北京时间（`Asia/Shanghai`）。
- 使用飞书原生标题，按 `1`、`1.1`、`2`、`2.1` 等形式连续编号。
- 使用七列原生表格记录版本或修改轮次。
- 技能开发类记录必须在正文中收录所开发技能当前 `SKILL.md` 的完整原文，包含 YAML 元数据，并将回读内容与源文件快照核对。
- 新记录统一保存到当前登录用户的个人文档库，创建后核对保存位置。
- 每次调用默认新建文档，不自动更新此前的工作记录。

## 使用要求

- 能够加载本地技能并运行命令的 Codex 环境。
- 已单独安装、完成登录授权的 `lark-cli`，并拥有在个人文档库创建、读取及必要时修复文档的权限。
- CLI 环境中配套的 `lark-doc`、`lark-wiki` 和 `lark-shared` 技能。本仓库不附带这些技能或 CLI 程序。
- CLI 支持 `docs +script`、`docs +create --parent-position my_library`、`docs +fetch` 和 `wiki +node-get`。
- 如果使用文档中的 `zoneinfo` 日期示例或本地快照、校验辅助操作，需要 Python 3.9 或更高版本。

使用前可检查本机 CLI 是否支持相关能力：

```bash
lark-cli docs +create --help
lark-cli docs +script --help
lark-cli wiki +node-get --help
```

文档操作使用 `--as user` 身份。登录授权、资源权限和接口权限范围需要根据自己的飞书账号配置；本仓库不包含账号凭据。

## 安装

将仓库克隆到技能目录之外，再链接到实际配置的 Codex 技能目录。以下示例采用默认目录 `~/.codex/skills`，并假设该标识的技能尚未安装：

```bash
git clone https://github.com/zero-one-2024/work-record-to-feishu.git
mkdir -p ~/.codex/skills
ln -s "$(pwd)/work-record-to-feishu" ~/.codex/skills/work-record-to-feishu
```

如果安装位置已经存在，先检查现有目录或链接，再更新原有仓库或安装配置，不要直接覆盖。使用其他技能目录的 Codex 环境应替换为实际配置的位置。

## 调用方式

在需要归档的任务会话中调用：

```text
$work-record-to-feishu 编写工作记录
```

例如：

```text
使用 $work-record-to-feishu 整理当前任务的开发过程，保存到飞书我的文档库。
```

智能体会根据当前会话中有依据的事实准备 XML 草稿，完成检查后创建文档，回读核对并返回飞书链接。如果只要求讨论方案或生成本地草稿，不会创建云文档。

技能开发类记录收录的是本次任务实际开发或修改的技能原文，而不是编写记录时调用的其他辅助技能。涉及多个交付技能时，分别收录其原文。

## 文档格式

默认大纲按实际工作内容调整，没有内容的章节会省略。

```text
1 任务概述
1.1 工作背景
1.2 目标与要求

2 工作内容
2.1 主要完成事项
2.2 关键方案与决策

3 版本迭代记录
3.1 迭代明细

4 工作成果
4.1 交付物与访问方式
4.2 验证结果与当前状态

5 后续事项
5.1 待完成或待确认事项

6 技能文件原文（仅技能开发类任务）
6.1 SKILL.md
```

版本迭代表格列为：

| 版本／轮次 | 日期 | 触发问题或需求 | 主要修改内容 | 验证记录 | 结果与后续事项 | 证据／附件 |
| --- | --- | --- | --- | --- | --- | --- |

使用真实版本标识和事件日期，没有版本号时用工作轮次描述，缺少证据时明确说明。制品生成、本地测试通过、部署和验收分别记录，不相互替代。

完整格式要求见 [record-format.md](references/record-format.md)。

## 创建与验证

文档创建步骤遵循 CLI 的创作工作流，并指定以下保存位置：

```bash
lark-cli docs +create \
  --doc-format xml \
  --content '@./draft.xml' \
  --parent-position my_library \
  --as user \
  --format json
```

这条命令是工作流中的创建步骤，不能替代草稿准备和检查。具体操作以已安装的 `lark-doc` 技能及当前 CLI 版本为准。

创建后核对文档名称、标题编号、表格结构、相关附件及个人文档库归属。对于技能原文章节，将 XML 转义与换行还原后，与保存的源文件快照比对。压缩包附件或源文件链接不能替代正文中的完整原文。

如果文档已创建，但附件写入失败，仅修复本次创建的文档。创建请求超时且结果不明时，先检查已有响应和文档状态，再决定是否重试，避免重复创建。
